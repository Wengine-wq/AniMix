# Настройки и диагностика

## DataStore Preferences 1.3.0

`AppSettings` сохраняет прежний API `state`, `load`, `update`, `flush`, но работает с `settings.preferences_pb`. Скалярные настройки используют типизированные ключи Preferences; словарь выбранных озвучек хранится отдельной строкой JSON. Изменение состояния интерфейса происходит сразу, запись идёт последовательно через транзакции DataStore.

- При первом запуске `DataMigration` читает `settings.json` и переносит все поля, включая параметры экономии батареи, отдельное предпочтение анимаций, качество и озвучки по тайтлам.
- Маркер схемы записывается в той же транзакции. После успешной миграции старый JSON не читается повторно и не изменяется: это резервная копия до перехода. При прерванной записи миграция может безопасно повториться.
- Действия пользователя во время загрузки применяются поверх сохранённых значений по порядку. Подтверждение записи не откатывает более новые изменения интерфейса.
- Одному каноническому файлу соответствует один экземпляр DataStore в процессе. Повторное создание экрана/Activity не создаёт конкурирующие хранилища.
- `flush` ждёт всех ранее отправленных изменений. Он вызывается при уходе Android в фон и закрытии desktop вместе с сохранением библиотеки, достижений и Watch flow.
- Повреждённый старый JSON сохраняется без изменений, ошибка декодирования попадает в журнал. В таком случае миграция использует настройки по умолчанию. Ошибки чтения или записи самого DataStore не считаются успешным сохранением.

Библиотека, покрытие просмотра, достижения и очередь не переносятся в Preferences: их формат и правила начисления XP остаются прежними.

## Kermit 2.2.0

Диагностика отправляется в платформенный журнал и в `data/diagnostics` внутри каталога приложения. Kermit-IO ограничивает файлы размером 256 KiB и хранит до трёх файлов. Облачная отправка не подключена.

`AppLog` принимает название подсистемы и код события. При ошибке записывает её тип; исходные сообщения исключений, stack trace с сообщениями причин, адреса видео, заголовки авторизации и личные списки не записываются. Это правило относится и к ошибкам Media3/VLC, импорта, сохранения и сетевых загрузок экранов. Обычная отмена корутины не считается сбоем.

## Проверка

Автоматические проверки покрывают перенос всех полей, однократность миграции, действия до загрузки, серию быстрых переключений, очистку nullable-параметров и одновременные изменения из нескольких источников. Отдельная проверка читает фактический журнал Kermit-IO и подтверждает, что токен и URL из сообщения исключения туда не попали.

Перетаскивание Watch flow проверяется настоящими pointer-событиями desktop-рендерера (мышь и touch), обычными кнопками, повторным запуском процесса и сохранением очереди. Это не заменяет проверку на физическом Android-устройстве.
