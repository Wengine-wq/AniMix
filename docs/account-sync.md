# Синхронизация онлайн-профиля

Существующие `AniMixAccount`, `Library`, `Achievements`, настройки, вход Google и
серверные API профиля/медиа сохранены. `AccountSync` — адаптер обмена поверх них,
а не новое хранилище приложения. Сервер — в этом репозитории, `server/` (PostgreSQL),
развёртывание — `server/deploy/`.

## Что переносится

- Имя, «О себе», закреплённое достижение, аватар и баннер. Изображения сначала
  загружаются существующим `PUT /v1/me/media/{avatar|banner}`. На сервер уходят
  серверные URL и идентификаторы; локальное имя файла остаётся на устройстве.
- Библиотека Shikimori **и YummyAnime**: статусы, избранное, оценки, счётчик серий,
  позиции, подтверждённые участки просмотра, исходные отметки импортированной
  истории и запись миграции 2.x.
- Обычные и исторические награды, даты, множества событий и прогресс. Исторические
  награды сохраняют источник и не превращаются в обычные или в XP.
- Дневное время и статистика по годам. Уникальные участки объединяются, а не
  складываются. Фактическое время складывается по устойчивым компонентам устройств;
  повтор HTTP-запроса, потеря ответа и повторный запуск его не увеличивают.
- Пользовательские предпочтения просмотра: тема, автопереход и пропуски,
  порядок избранного, озвучка и качество, выбор озвучки по тайтлам.

Файлы загрузок и очередь устройства, токены других сервисов, разрешения,
энергосбережение, анимации, сетевые настройки, отложенное обновление и активная
сессия Watch flow остаются локальными. Позиция серии доступна на другом устройстве;
автоматический удалённый запуск плеера и интерфейс передачи сессии Horizon Link
этим адаптером не подменяются.

## Обмен и конфликты

`GET /v1/me/sync` возвращает `{ revision, payload }`. Первый пустой ответ имеет
ревизию 0. `PUT` требует прочитанную ревизию: PostgreSQL атомарно сохраняет новую
ревизию либо возвращает **409** с текущим документом. Клиент объединяет изменения
и повторяет запись (до четырёх попыток за цикл). Ни старый `updatedAt`, ни часы
устройства не позволяют целиком затереть новую серверную библиотеку.

Объединение использует последнюю подтверждённую сервером копию, локальное и
серверное состояние. Независимые поля сохраняются с обеих сторон. Если оба
устройства изменили одно поле, при повторной записи побеждает локальное изменение
отправителя. Удаление оценки, избранного, изображения, позиции или записи списка
является изменением; старое устройство не восстанавливает его автоматически.
Уже подтверждённое покрытие объединяется независимо от редактируемых полей.

Изменения, внесённые во время HTTP-запроса, остаются на устройстве и отправляются
следующим циклом. Без сети сохраняются обычные локальные данные и журнал
синхронизации. Ошибка записи на диск не выдаётся за успешную синхронизацию.

Обмен запускается после инициализации и входа, после изменения данных и каждые
30 секунд при запущенном приложении. В «Настройки → Аккаунт» показано реальное
состояние и доступен ручной повтор. После перезапуска вход загружается сразу,
без обязательного открытия настроек. Фоновый серверный push не требуется.

Первое подключение сохраняет гостевую коллекцию и объединяет её с аккаунтом.
Существующие старые серверные списки при отсутствии нового документа загружаются
как импортированная история, без выдуманного просмотра. При смене аккаунта данные
предыдущего пользователя сохраняются в отдельном локальном кэше и не отправляются
следующему. Общие пользовательские предпочтения также отделены от нового аккаунта.
Выход оставляет данные на устройстве; локальные изменения относятся к прежнему
владельцу до следующего входа.

## Сервер

Добавлена таблица `user_sync_state`, без удаления или преобразования прежних
таблиц. Проверка ревизии и обновление редактируемых данных пользователя выполняются
в одной транзакции. Существующие профили и API чтения списков видят синхронизированные
поля. Приватность списков продолжает проверяться прежним API. Полный документ
доступен только своему владельцу и отдаётся с `Cache-Control: no-store`.
Медиа проверяются по ресурсам владельца; закрытый значок нельзя закрепить без
обычной либо исторической награды в передаваемой коллекции.

Сервер — `server/` этого репозитория (Node.js + PostgreSQL), развёрнут на VPS
из `server/deploy/`. Проверка двух установок против настоящего сервера:
`server/deploy/live-sync-test.ps1`.

## Проверки

`AccountSyncTest`: два устройства, независимые изменения, снятие отметок,
пауза сети, потеря подтверждения, 409, правки во время передачи, статистика без
дублей, сохранение происхождения истории, медиа и смена аккаунта.
`AccountSessionTest`: параллельные 401, единственное обновление токена, выход
во время обновления и точное совпадение адреса OAuth callback.

```powershell
.\gradlew.bat :shared:desktopTest --tests '*Account*Test*' --tests '*LegacyMigrationTest*'
```

Сервер: `npm run build` и `npm test` в каталоге API. Дополнительный интеграционный
прогон на настоящем PostgreSQL проверяет одновременные записи одной ревизии,
изоляцию двух тестовых аккаунтов, публичную проекцию и загрузку изображения.

30.10.2026 расширение развёрнуто на текущем VPS после резервной копии базы,
исходников API и прежнего Docker-образа. `scripts/sync-vps-smoke.cjs` прошёл
на настоящем PostgreSQL. `AccountSyncLiveTest` также прошёл: два экземпляра
клиентского кода со своими временными сессиями обменялись данными через публичный
HTTPS-адрес. Тестовый аккаунт и его сессии удалены. Этот прогон не использует
аккаунт пользователя и не заменяет самостоятельную проверку входа Google в UI.
