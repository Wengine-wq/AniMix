# Профиль и личное оформление

## Данные и редактирование

Ограничения имени и описания считаются по целым видимым Unicode-символам (grapheme clusters), одинаково в счётчике, редакторе и модели. Emoji, флаги, последовательности с ZWJ и комбинируемые знаки не обрезаются посередине. Используется `Regex("\\X")`, поддерживаемый [Android Pattern](https://developer.android.com/reference/java/util/regex/Pattern.html) и [JDK Pattern](https://docs.oracle.com/en/java/javase/20/docs/api/java.base/java/util/regex/Pattern.html).

`LocalProfile` — сохраняемая копия профиля. Старые `name` и `createdAt` совместимы с прежним JSON. Новые поля имеют значения по умолчанию: `about`, `avatar`, `banner`, `badgeAchievementId`, `updatedAt`, а также необязательные серверные `accountId` и `handle`.

`ProfileDraft` содержит только доступные пользователю поля. Применение черновика не может сменить ID аккаунта, публичный идентификатор или дату создания. Имя ограничено 35 символами в редакторе, при сохранении и загрузке старых профилей, описание — 160. Карандаш открывает редактирование всего профиля из правого верхнего угла рядом с настройками. Значок проверяется по набору открытых достижений; историческая награда тоже доступна для витрины и по-прежнему не даёт XP.

Редактор показывает результат до сохранения. «Назад» отменяет черновик. Сохранение меняет профиль одним обновлением библиотеки. Оформление не меняет расчёты уровня, просмотров или наград.

## Изображения

- Android использует системный Photo Picker через `PickVisualMedia`: доступ выдаётся к выбранному изображению. При недоступном Photo Picker AndroidX использует системный выбор документа. См. [документацию Android](https://developer.android.com/training/data-storage/shared/photo-picker).
- Windows использует выбор файла: PNG, JPG/JPEG или GIF; анимация GIF не переносится в оформление профиля.
- Изображение приводится к формату предпросмотра и сохраняется в приватной папке `profile-media`: аватар 640×640, баннер 1600×600. Обрезка по центру, без изменения пропорций. Исходный файл пользователя не меняется. Чтение и обработка выполняются вне потока интерфейса.
- В JSON хранится относительное имя подготовленного файла. Смена исходной папки или временное разрешение на фотографию не ломает сохранённый аватар.
- `ProfileMedia` отдельно содержит `localFileName`, серверный `assetId` и `url`. Когда локального файла нет, используется HTTP(S) URL; без доступной картинки остаётся штатное оформление.
- Неиспользованные изображения текущего редактора удаляются при отмене, заменённые — после сохранения. Исходные файлы и серверные ресурсы не удаляются.

## Подключение сервера позже

Сейчас профиль сохраняется на устройстве. Не добавлены вымышленные API, аккаунты или состояние «синхронизировано».

Адаптер синхронизации должен сначала загрузить новые локальные изображения и получить серверные `assetId`/URL, затем отправить редактируемые поля и выбранный значок. Локальные пути не должны попадать в публичный профиль. Сервер проверяет право на значок и принадлежность медиа заново; локальная проверка нужна для UI, а не заменяет серверную авторизацию. Политику конфликтов и ревизии задаст реальный API, `updatedAt` сам по себе её не решает.

## Проверки

- Старый JSON, сохранение и перезапуск, удаление изображения, сохранение серверной идентичности, запрет закрытого значка.
- Подготовка изображений и независимость сохранённого оформления от исходного файла.
- Тёмная и светлая темы, пустой профиль, длинное имя, шрифт 130%, мобильная ширина и desktop.
- Промежуточные кадры перетекания карусели, переход последнего баннера к первому, остановка таймера при взаимодействии и выключенных эффектах.
